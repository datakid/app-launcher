## 1. Mission

Make the app feel **buttery smooth and visually consistent** without changing what it is.

Three outcomes, in priority order:

1. **Tab switching stops rebuilding the world.** It is the single most felt interaction, and today it destroys and recreates every card.
2. **Every press responds on the first frame**, and the hover field stops burning CPU when the pointer is idle.
3. **The cards look deliberate**: one anatomy, one radius source, one hostname treatment, readable contrast, honest tap targets.

Explicitly **not** the goal: a redesign, new features, a new animation system, more effects, splitting the bundle, lazy loading, font changes, adaptive quality tiers, swipe pager, favourites, or a link editor. Those are deferred (section 9). If you finish everything here ahead of schedule, **stop**. Do not start section 9.

The look is already good. The problem is accumulation: four visual systems stacked as overrides, motion durations living in two places that disagree, and an entrance animation that pays a full DOM rebuild on every tab press. You are removing weight, not adding polish on top.

## 3. How to work

You are on a tight token budget. **Do not read `src/app.js` (270 KB) or `src/app.css` (204 KB) in full.** You will burn the budget and retain nothing.

For each ticket:

1. **Locate.** Search for the exact anchor string in the ticket (a function name, a selector, a token). Read **only** ~80–150 lines around it.
2. **Read the neighbourhood, not the file.** Before editing a function, read from its `const` line to its closing `};`.
3. **Write the smallest change** that satisfies the ticket.
4. **Build and check.** `npm run build && npm run check`.
5. **Capture before/after evidence** if the ticket asks for it (section 6).
6. **Commit** one ticket. Then update `vnext/NOTES.md` with one line: ticket ID, what you changed, any file you could not change as specified.

If a ticket's premise does not match the code: **do not improvise a bigger change.** Do the minimal correct version, write one line in `vnext/NOTES.md`, and move on. If the mismatch is structural (a function you were told to edit does not exist, or fixing it needs 4+ files), **stop that ticket** and leave a `BLOCKED:` line in `vnext/NOTES.md`.

### T2 — One source of truth for motion

**Goal.** JS and CSS use the same durations and the same curves, and nothing has to be reconciled at runtime.

**Why.** F5. `MOTION` (`app.js:916–943`), `--dur-*`/`--ease-*` (`app.css:2607–2624`), literal durations in rules, two different lux curves, and `.lx-switching` (`app.css:3497`) which rewrites every `--dur-*` on the bar during a switch to hide the mismatch.

**Scope.** The two token blocks in `app.css`; `EASE_LUX` and the `MOTION_*` tables and the `--lx-*-ms` writes in `app.js:908–949`; `switchClamp` and its call site; the `.lx-switching` rule. Nothing else.

**Steps.**

1. In `app.css`, make the `:root` block authoritative for motion. Keep the existing `--dur-*` names exactly (`--dur-micro`, `--dur-fast`, `--dur-base`, `--dur-slow`, `--dur-story`, `--dur-ambient`, `--tab-dur`, `--dur-tap`) and the existing `--ease-*` names. Add **four role aliases** that point at existing curves, so no new curves enter the codebase:
   ```
   --ease-enter: var(--ease-out);
   --ease-exit: var(--ease-out);
   --ease-move: var(--ease-smooth);
   --ease-emphasis: var(--ease-spring);
   ```
   Do not rename or delete `--ease-io`, `--ease-snap`, `--ease-pill`, `--ease-spring`, `--ease-smooth`, `--ease-lux`. Something uses each of them; prove it with a search across `src/` before removing anything, and remove nothing you cannot prove unused.
2. Add one bridge token set for the values the JS currently writes inline at `app.js:944–949`. Keep those writes (they are the mechanism), but express the numbers from CSS where a CSS equivalent already exists.
3. Adopt **one lux curve**: `cubic-bezier(0.22, 1, 0.36, 1)` — the CSS value. Change `EASE_LUX` at `app.js:908` to read it once from the document at boot:
   ```
   const EASE_LUX = getComputedStyle(document.documentElement).getPropertyValue('--ease-lux').trim() || 'cubic-bezier(0.22, 1, 0.36, 1)';
   ```
   This **will** visibly change WAAPI transitions (palette, QR, cards). That is intended and it is the point: one curve, not two. Do not try to make this a zero-diff change; it cannot be one.
4. Remove `.lx-switching` (`app.css:3497`) and the `switchClamp` machinery (`app.js:959–969` and its call sites). Delete the `--lx-switch-ms` writes with it. If a call site is inside a branch you do not understand, read that branch before deleting.
5. In `MOTION_NEW` / `MOTION_LEGACY`, align each `*Ms` value that duplicates a `--dur-*` token so the token is the number. Where a table value has no token (e.g. `inDelay: 60`, `stagger`), leave it — it is a delay, not a duration.

**Acceptance.** One lux curve in the codebase (search `0.16, 1, 0.3, 1` → zero hits outside git history; search `0.22, 1, 0.36, 1` → one definition plus the read). `lx-switching` gone. No literal duration duplicated between JS and CSS for the same role. Owner signs off the palette and QR open/close at 0.25× speed from a screen recording, because this ticket changes their feel by design.

**Verify.** `npm run check`. Then open palette, QR, tab switch, view switch by hand in both themes and both languages; confirm nothing snaps instantly and nothing lags.

**Rollback.** Revert the commit. It is self-contained.

### T4 — Pointer field: stop working when nothing moves

**Goal.** The hover field costs nothing when the pointer is still or far from the grid.

**Why.** F8, corrected. De-duplication already exists (`setIfChanged`, `app.js:2082`) and rects are already cached (`measure()`, `app.js:2020`). The remaining cost is that `subscriber.fixed(dt)` integrates **seven springs per card, every frame**, while writing registered custom properties that **inherit**, so each write invalidates the card's subtree. On a 20-card grid that is 140 spring integrations and a subtree recalc per frame, forever.

**Scope.** `initPointerField` and its subscriber (`app.js:1989` to its end); the `@property` registrations at `app.css:202–206`; possibly the card rule that consumes `var(--sc)`.

**Steps, in order. Stop when `perf:recalc` improves and the hover looks identical.**

1. **Idle stop.** In the subscriber, after integrating, detect full rest: every card's springs have `|velocity| < 0.01` and `|to − current| < 0.001`. When at rest **and** the pointer has not moved for 250 ms, unsubscribe the frame callback (or return early before any style write) and re-arm on the next `pointermove` / `scroll` / `lx-scrolling` end. This alone removes the idle battery drain.
2. **Radius gate.** For cards whose centre is further than `REVEAL_RADIUS * 1.6` from the pointer, write their rest values **once** (a single `setIfChanged` call with the rest value, which the existing epsilon makes a no-op afterwards) and skip them in the spring loop entirely. Keep `computeFalloff()` semantics; it is already focal-cached.
3. **Inheritance.** Search `src/app.css` for `var(--tx)`, `var(--ty)`, `var(--hov)`. 
   - If **no descendant** selector uses them (only `.app-card` itself and its own pseudo-elements), flip those three `@property` registrations to `inherits: false`. That stops the subtree invalidation.
   - If a descendant does use them, **do not flip it.** Instead find which descendant needs it and write the value directly to that element, or hoist the consumer to the card. Record what you found in `vnext/NOTES.md`.
4. **Fewer springs.** Only if steps 1–3 are insufficient: derive tilt from two springs instead of integrating `tx`, `ty` and `tz` separately, keeping the same visual response. Do not change the spring constants to make the numbers look better; identical output or revert.

**Acceptance.** `npm run perf:recalc` before/after in `MEASUREMENTS.md` with a lower style-recalc figure. A trace of a hover sweep shows a shorter scripting + recalc bar. Hover, tilt, dim and reveal look identical in a side-by-side recording at 390px mobile **and** 1280px desktop (the field only runs on `MQ.hoverFine`, so test with a real pointer). Card entry animation still plays on first load.

**Verify.** `npm run check`, `npm run perf:recalc`, 8 screenshots, plus a manual hover sweep in both themes.

**Risk.** The field is the most stateful thing in the file. If you break it, cards freeze mid-tilt or stay dimmed. Test: move the pointer across the grid, leave the window, open and close the palette, open and close the QR dialog, switch tabs, scroll — cards must return to rest every time.

**Rollback.** Revert. Do not attempt to patch a broken field in place twice; revert and start the ticket over.

### T5 — Tab switch without rebuilding the grid

**Goal.** Pressing a tab shows the already-built grid instantly.

**Why.** F7. `renderCards()` (`app.js:1861`) does `grid.innerHTML = ''` (`app.js:1941`) and rebuilds every card, then `cardDistances()` (`app.js:1958`) reads a rect for each new one, then the entry animation restaggers from scratch. Switching back to a tab you visited 2 seconds ago pays the full cost again.

**Scope.** `renderCards`, `activateTab` (`app.js:3270`), `runGridSwitch`, and the cache. `app.css` only if a hidden-container rule is needed.

**Approach — cache the children, keep the DOM shape.** Do **not** introduce per-category wrapper divs. `#appGrid` is the scroll container, the grid, the `aria-labelledby` target and the skip-link target, and `qa/card-layout.mjs` and `qa/behaviour.mjs` select `#appGrid > .app-card`. Restructuring the tree will fail those tests and is a large, unnecessary risk.

Instead:

1. Add a module-level cache `const gridCache = new Map()` keyed by `categoryId`.
2. In `renderCards`, **before** doing anything else: if the cache has this key and the cache is valid, then
   - stash the current children into a fragment and store them under the **current** tab's key,
   - move the cached children back into `grid`,
   - restore the cached inline grid styles (`gridTemplateColumns`, `gridTemplateRows`), `dataset.layout`, `dataset.rows`, `classList` entries (`is-auto-flow`, `has-overflow`, `at-bottom`), `grid._icItems`, `grid._icCols`,
   - set `pointerFieldDirty = true`, re-`observe` icons if `grid._icItems`,
   - restore focus if the previous grid held it (`hadFocusInGrid` logic already exists at `app.js:1864`),
   - return `false` (not a boot batch).
3. On a miss, build as today, and **after** appending also store the built children + inline styles + class state under the key.
4. **Invalidation.** Wrap the cache in a `dataVersion` counter. Bump and `gridCache.clear()` on: language change, theme change **only if** the card content depends on it (check first — if content does not change with theme, do not clear), look/palette change, view mode change (`bento|list|icons`), data import, reset, personal-links change, catalogue reload, and any icon manifest update. A stale cache is the one way this ticket produces a visibly wrong grid, so make the key explicit: `categoryId + '|' + lang + '|' + viewMode + '|' + dataVersion`. Simplest correct implementation: derive the key, and clear the map whenever `dataVersion` changes.
5. Reads before writes. In `staggerCardEntry` / `cardDistances`, collect all rects first, then apply all animations. On a cache hit, **skip the entrance animation entirely** — the cards are already on screen conceptually; animate only opacity 0→1 over `--dur-micro` so the switch is not a hard cut. Honour reduced motion with no animation.

### T7 — Blur only where content moves beneath it

**Goal.** Remove paint cost that buys nothing visible.

**Why.** F9. Seven surfaces carry `blur(12px) saturate(150%)` (`app.css:3515–3518`), including the tab rail nested **inside** the already-blurred bar — a blur inside a blur. Then the blur is stripped with `!important` on every scroll (`app.css:3523–3528`, driven by `app.js:950–957`) and restored 150 ms later, so the glass visibly pops during a scroll.

**Scope.** The blur list, the strip rule, and the scroll handler's class toggle.

**Steps.**

1. Audit each surface in the list against one question: **does content actually move beneath it?**
   - `.lx-bar` (sticky top): **keep blur.** Cards scroll under it.
   - `.tab-rail` inside `.lx-bar`: **remove.** It is nested inside a blurred parent; the double blur is invisible and doubles the cost.
   - `#lx-palette`: **keep blur.** The grid is behind it.
   - `.app-grid[data-layout="list"]`: **remove.** A full-viewport surface blurring itself has nothing behind it worth blurring.
   - `.controls-pill`, `.lx-context-menu`, `.lx-toast`: **remove.** Small, transient, and content behind them is diffuse anyway. Replace with `background-color: color-mix(in oklab, var(--bg) 92%, transparent)` — the exact fill already used in the strip rule, so it will look correct.
2. Remove the nested-blur case even if you decide to keep everything else: a blur inside a blur is never right.
3. Re-check the `prefers-reduced-transparency` path (`app.css:2600`) and `forced-colors` — both must still kill the effect cleanly.
4. Only after the blur count is down, try removing the scroll-time stripping (`html.lx-scrolling :is(...)` at `3523–3526`). Keep the `html[data-lowend]` half — that is the genuine low-end fallback. If removal shows no long frame during a scroll in DevTools' performance panel, delete the `lx-scrolling` class toggle from `onAnyScroll` too. If it does show new long frames, restore the strip and note why.
5. Do not change `isLowEnd()` (F10) or the `data-lowend` attribute. Adaptive tiers are section 9.

**Acceptance.** Frame times during scroll and palette open equal or better. Screenshots differ **only** on the surfaces you changed, and the owner approves each changed surface side by side. No visible pop while scrolling.

**Verify.** `npm run check`, `npm run perf`, a 10-second scroll trace, 8 screenshots.

**Risk.** Light theme is where a removed blur is most visible, because the opaque-ish fill over a light background can band. Check `data-theme="light"` explicitly, and the Vivid palette which overrides `--surface`.

**Rollback.** Revert. Never leave the code in a state where blur is stripped on scroll and never restored — that is a visible bug.

### T8 — Press feedback on the first frame

**Goal.** Every tappable thing visibly acknowledges a press immediately.

**Why.** Roadmap §5 target: first visual change within one frame of a press. On `:hover`-capable devices the pointer field gives this for free; on touch and keyboard it does not.

**Scope.** `app.css` state rules; no JS unless the `--sc` conflict in step 3 forces it.

**Steps.**

1. One shared state rule for `.app-card`, `.icon-plate`, `.tab-btn`, `.variant-chip`, `.controls-pill button`, `.lx-context-menu button`, and the QR trigger.
2. **Cards are special.** `--sc` is registered non-inheriting at `app.css:205` and is almost certainly consumed by a `scale:` declaration on `.app-card`. A bare `:active { scale: .985 }` would fight the pointer field and the `cardEnter` keyframes (which also animate `scale`). Instead find the rule consuming `var(--sc)` and multiply:
   ```
   scale: calc(var(--sc, 1) * var(--press, 1));
   ```
   then set `--press: .985` on `:active` with a ~60ms transition on `--press` in, and `--ease-emphasis` out. If `--sc` is **not** consumed by a `scale:` declaration, say so in `vnext/NOTES.md` and use a plain `scale` on a non-animated child instead.
3. Everything else: `:active { transform: scale(.97) }` with a 60ms in and `--ease-emphasis` out. Do not touch `transform` on `.app-card` — the entrance animation owns it there.
4. Keyboard: `:focus-visible` already has a ring (global rule near `app.css:216` and the light-theme override). Do not remove it. Press feedback must not replace it.
5. Touch: `touch-action: manipulation` and `-webkit-tap-highlight-color: transparent` are already applied globally to `a, button, [role="tab"], [role="option"]` (`app.css:216`). Do not duplicate. Confirm the cards' overlay link receives them — if the actual tappable element is `.card-link-overlay`, it needs the same two declarations.
6. Verify no layout shift: `scale`/`transform` never reflow. Watch for a card's shadow clipping at the grid edge — `.app-card` has `contain: layout paint style` (`app.css:3529`), so a scaled press may clip its own shadow. If it does, the press scale goes on `.card-clip` instead.

**Acceptance.** In a DevTools performance trace, the first paint after `pointerdown` is ≤ 1 frame. `qa:motion` passes (only `opacity`, `transform`, `translate`, `scale`). Press feels instant on a phone in both themes and both languages.

**Verify.** `npm run check`, trace, manual test on the mobile viewport with touch emulation.

**Rollback.** Revert. Purely additive CSS, so this is a safe revert.

## 8. Regression traps, ranked by how likely they are to bite you

Read this before every commit.

1. **Stale cache (T5).** The grid shows the old language or the old personal links. It will look fine until someone switches language. Test that path explicitly.
2. **Frozen hover (T4).** A card stops returning to rest, or stays dimmed after the palette closes. Test palette open→close→hover, QR open→close→hover, tab switch→hover.
3. **`!important` escalation.** The file already has 20+ of them. If your rule does not win, you are almost certainly adding to the wrong part of the cascade — inspect the winning rule in DevTools first. Adding `!important` to beat an override is how this file got to 204 KB. Do not.
4. **`@layer` inversion (T3).** You are not adding layers. If you are tempted to, re-read T3 step 5.
5. **Duration mismatch reintroduced (T2).** Someone left a literal `260ms` in a rule that duplicates `--dur-fast`. That is exactly the defect T2 removes; grep for `ms` in the motion region when you finish.
6. **Blur removed where it was load-bearing (T7).** Text over the moving background becomes unreadable. Check the sticky bar at both themes with cards scrolling under it.
7. **RTL assumed (T9, T6).** A new `margin-left` in a card rule. Use logical properties only.
8. **`dist/` hand-edited.** It gets regenerated and your change vanishes; you then "fix" it twice. Never edit it.
9. **A test weakened to pass.** If `qa/cards`, `qa/tiles`, `qa:motion`, `qa/load` or `perf --assert` fails, the default assumption is that your change is wrong. If the test genuinely encoded the old behaviour you were asked to change, change the test in the **same commit** and explain it in `vnext/NOTES.md`.
10. **Two tickets in one commit.** Then the revert is a choice between two changes, and you will pick wrong.

## 10. Definition of done

A ticket is done when **all** of these are true:

- [ ] `npm run check` green, output pasted or summarised in the commit body.
- [ ] Before/after evidence in `vnext/MEASUREMENTS.md` (perf tickets) or 8 screenshots (visual tickets).
- [ ] Both languages, both themes, all three views checked by hand.
- [ ] Reduced motion checked (T6, T8, T10 in particular).
- [ ] No new comment in `src/`, `build/`, `qa/`, `tools/`, `perf/`, `harvest/`, `compare.html`, `vercel.json`.
- [ ] No new dependency, no build-config change.
- [ ] `vnext/NOTES.md` updated with what changed and anything you could not do as specified.
- [ ] One commit, message `vnext(T#): summary`.

The release is done when T0–T9 are committed (T10 optional if the budget runs out), `dist/` is rebuilt by `npm run build`, and the owner has approved the T6, T7 and T9 recordings.

**Then freeze.** Tag it. For 30 days, fix bugs only. The app is already better built than most tools of its kind — the remaining rough edges are consistency, and consistency is now done. Adding to it is what produced 280 commits, and it is what T2 and T3 exist to make expensive again.

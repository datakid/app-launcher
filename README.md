# LinkExpress

A bilingual (Arabic/English) launchpad for internal tools. A static site built from `src/` into `dist/` by `npm run build`, driven entirely by `links.json`.

## Mobile layout (≤ 640px)
- Compact header: title on the start side, a small utility pill on the end side (theme, look, language, data, refresh). Zen and sound stay on desktop and in the `>` command palette
- Full-width search bar that sticks to the top while scrolling
- Category tabs become a fixed bottom tab bar with icons and labels, padded for the safe area
- Cards sit in a 2-column grid with a natural height; if the count is odd, the last card spans both columns. Variant chips fill the card width, and a card grows taller when its badges stack so they never reach the icon or the QR chip
- Desktop (> 640px) is unchanged

## Editing links
`links.json` is the source of truth. The build bakes a copy into `dist/index.html` (`<script id="lx-data">`, filled with `JSON.stringify` from `links.json`) so the first paint is instant, even offline or on a first visit, and the copy can never drift from the file.

- Load order: localStorage cache, then the baked-in copy, then `links.json` fetched quietly in the background once the page is idle
- The **refresh** button (last button in the top-left pill, or the "Refresh tools" command after typing `>` in the palette) forces a network fetch of `links.json` that skips the cache and tells you whether anything changed
- To publish a change, edit `links.json` and push. Vercel runs the build, which refreshes the baked-in copy. Visitors who already have the site also pick the change up through the background fetch of `links.json`

- Any Font Awesome 6 **solid** icon name works (`"icon": "fa-rocket"`). Icons already inlined in the page render instantly; any other name is fetched once from jsDelivr and falls back to `fa-circle` if the name does not exist
- Visitors see changes on their next visit. The last good catalog is cached in `localStorage`, shown immediately, then silently refreshed from `links.json`
- If `links.json` has a JSON syntax error, the cached version keeps showing (first-time visitors see "Could not load the tool list"). Check with `?lxdebug=1`, which also warns about rejected entries

## Features
- Bento grid of tools by category, with variants, "New" (auto-expires 30 days after `since`) and "Closed" badges
- Command palette (⌘K / Ctrl K, `/`, or start typing) with recents, frequent tools, Arabic-aware fuzzy search and actions
- Theme, language, sound and Zen mode, all saved in `localStorage`
- My data menu: import personal links (they go into a "My Links" tab), export data, remove imported links
- Pointer light: glass rim highlights with an opposite-edge glint, a soft inner glow and a sweeping sheen
- Focus falloff: when you hover a card, the others recede by distance (0.90 opacity for neighbours down to about 0.74 for the farthest, plus a slight scale-back). It starts after 110 ms of intent, so passing over cards doesn't flicker
- Cards: an accent glow in the corner, a hostname line under the title and an accent-tinted border on hover
- Palette scopes: category chips with live match counts and a sliding highlight. Shift+Tab cycles through them
- Command palette: flat keycaps, a quiet cursor, a strong primary action, dot-separated hints and a live status dot
- Visual system (v2): accent-aware gradient rim on the bar and palette, glass surfaces with a stronger blur, a circular magnifier badge on the bar and palette input, a tab indicator with an inner accent glow, active-state dots on the controls pill, an accent hairline across the top of each card, refined icon tiles, tinted variant chips and a more legible hostname line. Motion timings were tightened across the board (springs, tab switch, palette morph, card entry) so animations feel snappy and never block interaction

- Visual system (v3, "mature"): a single override layer at the end of the stylesheet. Calmer, lower-chroma colour tints (oklch); smaller corner radii (cards 18px, palette 20px, chips and badges 6–9px); flatter icon tiles with less gloss and no tilt on hover; quieter hover glow, sheen and watermark glyph; small-caps style badges with letter spacing; a hostname line in the UI font with a hairline lead-in; a solid title with a soft tone fade and fine rules on either side; hairline keycaps; and a palette cursor, primary action and scope indicator without the coloured glow. Background orbs are less saturated. All motion timings are unchanged
- Visual system (v4, layered tiles): every tile is built from layers instead of one flat fill. Tile tokens `--tile-hi`, `--tile-lo`, `--tile-shade` and `--glyph-accent` are derived from the tool's tint in OKLCH (highlight hue −12°, deep hue +14°, lightness clamped so white on the tile stays at 3.0:1 or better), with a static fallback for browsers without relative colour syntax; Mono uses neutral tokens and Muted keeps ink on paper. The stack is a plate (`::before`: a radial specular over a directional gradient, with five shadows: a hairline ring, a contact shadow, one ambient shadow sized from the tile, an inner top highlight and an inner bottom edge), a blurred hover blob (`::after`, one static blur) and the glyph on top; Arabic mirrors the light direction. Hover drives opacity, translate and scale directly: the pointer card gets `is-hot` and the blob only fades and moves, with no registered `--icon-lift` property and no transition on a custom property. Corners are squircles through `corner-shape: squircle` where supported (not in Crisp), and the glyph is filled from a shared gradient with a tinted depth shadow; two-layer symbols paint their secondary plane with `--glyph-accent`. Favicon marks sit on a neutral pedestal in light and dark, glyph size follows the manifest's `ink` value so tiles feel even (`--glyph-scale` is the square root of 0.29 over `ink`, applied with `scale`, and `ink` is filled for all 35 entries by `node tools/icons-v2.mjs --metrics`), and closed tools get a calm plate (icon 0.78, label 0.7, no grayscale). Per view: Bento has a quieter watermark and a press on fine pointers, List uses one shadow tier and a 1px tile lift, Icons has a new label type, hover lift with the blob, a localised New pill, refined glass plates and a quiet closed pill. Chrome: 15px controls-pill icons with an accent-tinted pressed state and one group divider, a search-bar focus ring that fades in on its own element, tuned magnifier, keycap and tab icons, and 40% less background grain. Motion rules: only transform, opacity, translate, scale, rotate and a few colour properties animate, never box-shadow, filter, background, size, inset or border-radius on tiles, cards, rows or plates; `will-change` is set only on hover and press; reduced motion, `html[data-lowend]` and `html.lx-scrolling` still switch effects off. `npm run qa:motion` enforces this from computed styles
- Search v2: the palette runs on `src/search.js`, a DOM-free module that builds one index per catalogue or language change and answers each query in a single pass. Fields are weighted: title, variant, parent tool, acronym, host, URL, category, id, icon name, status and badge. A match falls into a tier: exact, prefix, word start, acronym, substring, subsequence, or typo (edit distance 1 for 4–7 letters and 2 for 8 or more, never for shorter tokens, and ranked after every non-typo hit). Every word of the query must match (AND), Arabic is folded (hamza forms, alef maqsura, ta marbuta, diacritics, tatweel, Arabic-Indic digits) and so are Latin accents and an article-less form matches too, a pasted URL or host finds the tool it belongs to, and when nothing matches a query typed on the wrong keyboard layout (Arabic 101 against QWERTY) is swapped and tried again. Closed tools rank lower, the current tab and recent picks rank slightly higher, and ties are broken deterministically. Typing narrows the previous candidate set when that is exact. The palette makes one `search()` call per render, takes the scope counts from it, highlights from its match ranges, and shows what matched (host, URL, id, icon, status, badge or acronym) in a small `via` line on the category line without changing the row height. Command search (`>`) uses the same tiers on titles only, and the 55 ms debounce is replaced by one `requestAnimationFrame`. Speed: building the index for the real catalogue takes about 1 ms and a query about 0.03 ms; on a seeded synthetic catalogue of 5000 entries a cold query takes a median of about 2–5 ms and stays under 12 ms at p95 (`npm run qa:search` fails above 6 ms and 12 ms)
- **Appearance menu** (sliders button in the controls pill). Two independent settings that work in both light and dark mode, so there are 4 × 3 × 2 combinations:
  - **Colors**: **Vivid** (default) keeps each tool's own hue with richer chroma, a stronger aura, glow and rim, more saturated background orbs, and the full v2 gradient set: glossy three-tone icon tiles, the accent shimmer on the title, card title tint fades, the tinted bar, tab indicator, palette glow, cursor, primary action and detail slab. These are scoped to `[data-palette="vivid"]`, so the other looks are unchanged. **Curated** maps each colour to the nearest of eight shared tones (`CURATED_TONES`). **Muted** is a calm, editorial look of its own. Warm paper and espresso backgrounds; flat tinted icon tiles with the glyph in the tool's own ink instead of glossy gradients; solid titles with no shimmer; no glow, sheen or pointer light; a fine accent hairline on each card; hollow badges; quiet, low-saturation background orbs; and warm-toned bar, palette, menus and toast. Each tool keeps its own hue, blended 42% toward a warm grey (`MUTED_GREY`). **Monochrome** turns everything graphite: no hue on cards, icons, tabs, favicon or orbs
  - **Corners**: **Balanced** (default, 18px cards), **Soft** (24px cards, pill chips and badges) and **Crisp** (10px cards, and the bar, tabs and controls become rounded rectangles). One set of `--r-*` tokens drives every radius, including the tab indicator's clip-path
  - Switch with the menu, the palette commands (`>` then "Colors: …" / "Corners: …"), Alt+P (next colours), Alt+R (next corners), or `?palette=vivid|curated|muted|mono` and `?corners=balanced|soft|crisp` (URL parameters override the saved choice without saving it). Saved as `lx-palette` and `lx-corners`, applied before first paint, synced across tabs, and included in export/import prefs
  - A change crossfades in 280 ms through a View Transition (instant with reduced motion). Pure CSS variable swap: no re-layout of the grid and no extra animation loops, so motion and frame budget are unchanged
- Title rendering: the non-vivid title rule sets `background-clip: text` itself, so the title's gradient can no longer paint as a solid block behind the text when the base clip gets overridden (this was the dark rectangle). Muted goes back to plain solid ink
- Final polish pass: balanced title wrapping, inline padding so italic glyph edges aren't clipped, kerning on all UI text, header hairlines centred on the title, slightly stronger hostname/muted ink, steadier hostname opacity, and badges set to line-height 1
- No-flicker updates:
  - **Colors change** (menu, Alt+P, palette command, another tab): retints the existing cards, tab accent, palette rows, scope chips and detail by updating `--c1` / `--tab-accent` in place. The grid, tab rail and palette list are no longer torn down, so focus, hover, variant selection and scroll position all survive. It still uses the 280 ms crossfade
  - **Appearance menu**: clicking an option updates the checkmarks in place instead of re-rendering the menu, so the entry stagger doesn't replay and focus stays put
  - **Card right-click menu**: the New tab / Same tab switch slides its thumb and reorders the open rows in place instead of closing and rebuilding the menu
  - **Language switch**: wrapped in the same crossfade, so the RTL/LTR flip and the re-rendered labels land in one frame instead of jumping
  - **Background catalog refresh**: if `links.json` changes while you're looking at the page, the swap crossfades and cards don't replay their entry animation. Keyboard focus on a tab is kept. Skipped (instant swap) while another transition or tab switch is running
- `compare.html` polish: self-hosted Inter, 1px pane gutters, custom select chevron with hover and focus states, and pane labels aligned on a shared baseline
- `compare.html` shows all four colour looks in a 2×2 grid, with theme and corner switches that apply to every pane
- Card glyph: a large, faint copy of the tool's icon sits in the corner of each card and drifts slightly with the pointer
- Zen mode persists across reloads (`lx-zen`), is applied before first paint, and travels with export/import prefs. In Bento it widens the grid; in List and Icons the panel stays vertically centred and gets larger rows (64 px) or tiles (76 px). The list is always one column and, like the Icons grid in Zen, is as wide as the search bar (880 px), so their edges line up. Partial icon rows are centred under the bar, and the grid repacks when the width changes. Between 1025 and 1639 px wide the Zen search bar sits below the controls pill so the two never overlap. Browsers without View Transitions use the FLIP fallback, which covers icon cards too
- Palette: a tappable close button (Esc keycap on desktop, × on touch). Closing or pressing Esc during the open morph cancels it instantly instead of being ignored
- Tab indicator: positioned with real `left`/`right` edges (not `clip-path`), so its inset accent ring stays visible all the way around, rounded ends included, both at rest and while it slides. The top highlight sits on a `::before` layer inset by 1px so it never covers the top edge of the ring
- Alt Account and Harvest: listed in `links.json` under the reserved `palette` category, so Harvest Studio sees every link, and shown only in the command palette (search "Alt", "البديل" or "Harvest") under an "Alt launcher" group. That category gets no tab and no cards, has no Reveal action and is left out of the random "Try" picks. The id `palette` is reserved like `mine`
- Short desktop windows (≤700 px tall) scroll instead of squashing the grid; very narrow phones (≤360 px) get a tighter controls pill
- Touch: hover effects only apply on fine pointers, a tap scales the pressed card to 96%, version chips, tabs and the controls pill are at least 44 px, Bento, List and Icons all scroll with the page (never an inner scroll area on a phone), and a horizontal swipe on any grid switches tabs
- One motion system: a single `MOTION` object holds the timings per interaction. Tab and view switches fade the old content out in 120 ms and the new content in over 220 ms after a 60 ms wait; version switches cross-fade in 120 ms; the command palette opens in 200 ms and closes in 140 ms; the Colors and language crossfade takes 200 ms; the first-load entrance takes 360 ms with a 120 ms offset plus up to 180 ms of distance-from-origin stagger. The stagger runs only at first load. `?motion=legacy` restores the earlier timings (190 ms out, 620 ms in, up to 150 ms of stagger) so the two can be compared; it is never saved and never shown in the UI. Crossfades that use View Transitions are skipped with reduced motion and on low-end devices (4 cores or fewer, or 4 GB of memory or less). Views only differ in the direction of travel (sideways on a tab switch, a small lift on a view switch). The outgoing grid and the incoming cards are never both at full opacity, only opacity, transform, translate and scale are animated, `will-change` is cleared when an animation ends, and phones up to 1024 px with view-timeline support use the same scroll-driven entrance in all three views. Reduced motion makes every switch instant
- Real favicons: each tool's own favicon and a palette-matched single-colour glyph are harvested into `icons/` by `harvest/fetch-icons.mjs` (192 px PNGs, glyph PNGs and `icons/manifest.json`; run it locally with `cd harvest && npm ci && npm run harvest`). `node tools/icons-v2.mjs` turns those files into the assets the page loads: `icons/glyphs.<hash>.svg` (a sprite of `<symbol>` paths drawn with `currentColor`), `icons/glyph-atlas.<hash>.webp` (an alpha-mask atlas for glyphs that a single-colour path cannot reproduce), `icons/atlas.<hash>.webp` (a favicon atlas, loaded only when a tool needs a favicon) and `icons/manifest.v2.json`, validated by `icons/manifest.v2.schema.json`. `tools/icons-v2.config.json` pins chosen glyphs to the image fallback. A version switch only changes `data-active-variant` on a card that already holds every version's mark, so it never fetches or decodes an image for vector glyphs. The build ships only `manifest.v2.json`, its schema and the three hashed assets; the v1 PNG files stay in the repository as pipeline input and are not deployed. A cached v1 manifest in `localStorage` is discarded on load. The icon fallback chain is: vector glyph from the sprite, then the glyph atlas, then the favicon atlas, then the Font Awesome icon from the inline sprite, so a tile never renders empty (`qa/behaviour.mjs` blocks `icons/**` and checks this). Each version's accent colour follows its own harvested tint and falls back to the colour authored in `links.json` when a version has no tint, so switching versions on a card changes its colour. The in-repo harvest viewer is gone: Harvest Studio, at https://harvest-studio-phi.vercel.app/, is what the palette's Harvest entry opens.
- **QR codes**: every Bento card and List row has a permanent labelled "QR" chip. In Bento the chip drifts with the pointer together with the New and Closed badges beside it. In Icons view a small round chip fades in on hover or focus, sits on the tile's top corner (in Arabic too) and lifts with the tile (hidden on touch, where long-press opens the context menu), and Alt+Q on a focused tile, the menu and the palette also work. The palette shows a QR chip on the highlighted row with a mouse and on every row on touch screens. Alt+Q with no card focused, or the "Share LinkExpress as a QR code" palette command, shows a QR for the site itself, and Alt+Q again closes the dialog. Tools with versions get a sliding version control inside the dialog and encode the selected version's URL. The code is drawn as rounded dots with rounded finder eyes in a dark tint of the app colour on a paper-white plate, with a four-module quiet zone, whatever the theme, and the app icon sits in the centre (error correction H, versions up to 8; longer links fall back to Q or M without the icon). The dialog opens and closes with CSS transitions driven by `MOTION.qr`, so reopening during the exit animation can't leave it invisible, and on phones it is a bottom sheet you can swipe down. Keys inside the dialog: C copies the link, P saves a PNG, S saves an SVG, I copies the image. PNG export is about 1024 px with a title and host caption (Alt-click for a bare code), SVG export is vector with a title and description, and Copy image uses the clipboard. Buttons report through an inline icon and label flash, not a toast, so focus stays in the dialog; Share appears only where `navigator.share` exists. `?qr=<app id>&v=<version id>` opens the dialog for that tool on load. Codes are generated in the page by `src/qr.js` (byte mode, error correction M, Q or H, versions 1–14, so links up to 362 bytes at M, longer ones show a message), with no network request, so they work offline
- Icons layout: tools with versions sit on a shared glass plate with a caption, single tools stand alone, and `src/icon-solver.js` (pure, no DOM) decides the rows. It never uses more rows than the minimum, keeps the order inside the plates and inside the singles, and balances the rows, so Core is 6 + 5, Experimental 5 + 5 and Tools 6 + 6 on a desktop; the output is the same on every run. Rows with spare room are centred. A tab or view switch animates each plate as one unit, so the glass panel and caption fade in with their icons and nothing shows through from the old grid. Neighbouring plates keep at least 12 px between their panels. A closed tool keeps its plate panel at full strength, dims its icons to 0.78, its labels to 0.7 and its caption to 0.5 without any grayscale, and shows a small hollow "Closed" tag beside the caption; hovering the plate shows the reason when there is one

## Card layout
- **Slots**: a Bento card is a header (icon, title, end slot) and a footer (hostname, variant chips). The end slot holds the New and Closed badges and the QR chip and is always part of the layout, never positioned over the icon. On the desktop hero card the same elements form one grid, `icon | title | chips | end`, so the icon, title, chips and end slot share a single baseline and never wrap onto a second row
- **Parallax**: the end slot moves with the pointer-driven card parallax, so the badges and the QR chip travel together with the icon. Reduced motion turns the parallax and the QR press scale off
- **One chip system**: badges, the QR chip and the variant control share a height token (`--chip-h`: 28px, 32px up to 1024px wide), a type setting and the corner radius of the current Corners set. The QR chip and variant chips keep a 44px touch target on coarse pointers through an invisible hit area, without growing
- **Fits its own size**: `.card-clip` is a size container, so the content follows the card and not the viewport. When two badges do not fit they collapse to dots, then the QR chip keeps only its icon, then a single badge collapses to a dot. The labels stay in the DOM for screen readers. In grids with four rows and short cards the icon shrinks and titles stay on one line with an ellipsis, and variant chips stack in the narrowest cards. The hero title stops at two lines with an ellipsis above 1024px
- **Icons view**: the QR chip sits in the top start corner of the tile, the new dot in the top end corner and the digit badge at the bottom end, in both directions. The new dot and the digit badge overhang the tile by 4 px and `qa:cards` checks that they stay inside the grid in the first and last column, in English and Arabic, at 390, 1280 and 1707 px
- **Focus**: the QR chip, the variant chips and the card link share one focus ring tinted with the card's colour

## Open mode and card menu
- **Default open setting**: links open in a **New tab** (default) or the **Same tab**. Change it in the Preferences menu (sliders button, "Open links" section), with the switch at the bottom of any card's right-click menu, with Alt+O, or from the palette command (`>` then "Open links in …"). Saved as `lx-open`, synced across tabs, and included in export/import prefs (`prefs.open`)
- The setting applies everywhere: clicking a card (its link target), the digit shortcuts 1–9, palette click and Enter (Shift+Enter uses the other mode), and the palette's primary action. The card's hover icon shows which mode is active
- **Card right-click menu**: a header with the tool's icon, name, active version, hostname and Closed state, tinted with the tool's colour. For single-link tools: both open options (the current default comes first and is tagged "Default"). For tools with versions: one row per version instead. Click the name to open that version now (the card keeps its version), ↗ opens it the other way (also Shift/Ctrl/⌘-click or middle-click), and the pin on the same row makes it the card's version (the set pin is filled; the menu stays open and its header updates). Then Copy link, Copy name (with a ✓ confirmation), Show details (opens the palette on that tool) and a two-way New tab / Same tab switch. It works with the keyboard (Shift+F10 / the menu key, ↑↓ between rows, ←→ across open / ↗ / pin, Home/End, Esc)
- Polish: refined menu glass and shadows, staggered menu entry, accent-tinted states on the controls pill (no dot), a toast with a status dot and spring motion, clearer hostnames and variant chip hovers, and a thin grid scrollbar

## Data model
- Catalog: `{ categories: [{ id, label{ar,en}, icon, accent, key, apps: [{ id, title{ar,en}, url | variants[{id,label,url,icon}], defaultVariant, icon, gradient[3], closed, closedReason, isNew, since }] }] }`
- IDs: lowercase letters, digits and `-`, up to 40 characters, unique. Colors must be `#rrggbb`. URLs must be `https:`
- Limits: 12 categories, 24 apps per category, 4 variants per app, 256 KB file
- Import file: `{ "links": [{ "title": "..." | {ar,en}, "url": "https://...", "icon": "fa-...", "color": "#rrggbb" }], "prefs": {...} }`
- localStorage keys: `lx-user-links`, `lx-catalog-cache`, `lx-theme`, `lx-lang`, `lx-sound`, `lx-zen`, `lx-variant-*`, `lx-recents`, `lx-freq`, `lx-last-tab`, `lx-last-open`, `lx-palette`, `lx-corners`, `lx-open`, `lx-icons` (cached icon manifest), `lx-glyphs` (cached icon sprite)

## Build, deploy and cache
- `npm ci && npm run build` writes `dist/`. Vercel runs the same command on every push (`vercel.json`: `npm run build`, output directory `dist`); the project's root directory is the repository root. Harvest Studio is a separate Vercel project
- Hashed files (`app.<hash>.css`, `app.<hash>.js`, the icon atlases and sprite) and fonts are served with `Cache-Control: public, max-age=31536000, immutable`; `index.html`, `sw.js`, `links.json` and `icons/manifest.v2.json` are served with `no-cache`
- The service worker precaches the page, its hashed files, the icon sprite, the glyph atlas, four fonts, `favicon.ico` and `manifest.webmanifest`. Navigations are answered from the cache, so a repeat visit makes no network request before the grid appears and the page reloads offline. `links.json` and the icon manifest are answered from the cache and refreshed about two seconds later. Each new build gets a new cache name and old `lx-` caches are removed when it activates. It registers only on `https:` and on localhost
- Fonts: only the two faces used above the fold for the current language are preloaded (IBM Plex Sans Arabic and El Messiri for Arabic, Inter and Cormorant Garamond for English), and every web font uses `font-display: swap`

## Harvest export contract
Harvest Studio is a separate project. The launcher keeps accepting the current manifest unchanged; the fields below are optional additions, type-checked by `icons/manifest.v2.schema.json` and validated on `icons/manifest.v2.json` by `qa/icons-schema.mjs` (inside `qa:icons`). Per icon key (`<appId>` or `<appId>--<variantId>`):
1. `<key>.glyph.png`: 192×192, transparent background, a pure white mark only with the shape in the alpha channel. No baked background, shadow, gloss or outline, because v4 adds all depth itself. The mark's bounding box fits the central 124×124 (about 64%), centred by its visual centre of mass
2. Two-tone marks (optional): put the secondary plane in the same PNG at a flat alpha of about 0.45–0.6 (±10) and the primary at 1.0. `detectMidLevel` and the layered tracing in `tools/icons-v2.mjs` turn that into a two-layer symbol that v4 paints with `--glyph-accent`. No gradients inside the PNG
3. `<key>.png` favicon: 192×192 or larger, the original brand icon, transparent where the source is transparent. `shape` is `"default"` unless the source is clearly a circle, squircle or hexagon
4. Manifest fields per entry:
   - `tint`: `[base, light, deep]` as `#rrggbb`, chosen in OKLCH. `base` has L 0.56–0.66 and C 0.09–0.16; `light` is L +0.12…+0.16 over base with hue −8…−14°; `deep` is L −0.18…−0.24 with hue +10…+16°. For yellows and olives (h 70–115) use C ≥ 0.11 and rotate the hue toward amber (−10°). White on `base` must reach 3.0:1
   - `ink`: the fraction of the 192×192 canvas covered by alpha ≥ 0.5 (0–1). The launcher reads only this field, for optical sizing
   - `bbox`: `[x, y, w, h]` of the mark in 0–1 units
   - `layers`: `1` or `2`, whether a mid-level plane exists
   - `tintRole`: `"brand"` when the tint came from the favicon, `"authored"` when it came from `links.json`
5. Consistency across the set: one stroke weight family (solid shapes, at least 2 px stroke at 24 px), no text inside glyphs except monograms of two letters or fewer, and similar ink (target 0.22–0.36)
6. `tools/icons-v2.mjs` copies `ink`, `bbox`, `layers` and `tintRole` from the v1 manifest into v2 when present. `node tools/icons-v2.mjs --metrics` only reads the existing `<key>.glyph.png` files and the v1 manifest and writes those four fields into `icons/manifest.v2.json`: it does not trace, encode, re-hash or touch the sprite, the atlases, `hash` or `generatedAt`

## Checks
- `npm run qa` runs the Playwright matrix (themes, languages, corners, viewports) against `dist/` when it exists; `npm run qa:quick` runs a subset. They check horizontal overflow, cut labels, tap targets, card presence and that `lx-data` equals `links.json`
- `npm run qa:load` checks the page weight (`dist/index.html` gzipped, at most 30,720 bytes, and the total first-load transfer, at most 266,240 bytes), that a repeat visit makes no network request before the grid, and the offline reload
- `npm run perf:recalc` runs `perf/recalc.mjs`: it interleaves two builds (`--base`, default `../lx-main/dist`, against the current site), repeats each scenario nine times in Chromium, and reports style recalculation count and duration, layout count, script and task time and the elements restyled by `UpdateLayoutTree`, as medians, for hover sweeps over Bento, List and Icons (`hover-bento`, `hover-list`, `hover-icons`), palette open and close cycles, tab switches, view switches and look cycles, on the desktop and mobile profiles at 1× and 4× CPU (`--profiles`, `--scenarios`, `--runs`). Results go to `perf/out/`; `--merge`, `--skip-done` and `--compare-only` resume and compare a long run
- `npm run perf` measures the interactions in `perf/interactions.mjs` on a mobile and a desktop profile and writes `perf/out/latest.json`; `--assert` compares it with `perf/targets.json`. When the `CI` environment variable is set the timing targets are skipped, because shared runners have no GPU, and only the image request and decode targets are asserted. Run it on real hardware for the timing numbers
- `node qa/visual-marks.mjs` writes screenshots of every icon surface in each palette and theme, and `node qa/shot-diff.mjs <before> <after>` compares two sets
- `npm run qa:behaviour` runs `qa/behaviour.mjs` and `qa/rapid-switch.mjs`: twenty version switches with no image request, the `?motion=legacy` timings, focus and scroll surviving an icon-manifest change, no running animation after any interaction under reduced motion, and ten tab clicks 40 ms apart ending on the last tab. Add `--timing` to `qa/behaviour.mjs` and `--strict` to `qa/rapid-switch.mjs` on real hardware to also assert the frame and settle times
- `npm run qa:qr` runs `qa/qr-encoder.mjs` (the encoder against jsQR for versions 1–14), `qa/qr.mjs` (menu, palette, site and keyboard entry points, version switching, Arabic, phone width, reduced motion and offline, plus every palette x theme x direction combination, each decoded from a screenshot of the rendered code) and `qa/qr-stress.mjs` (rapid toggling, reopening during the exit animation, palette handoff by key, mouse and touch, and every way of closing, at 4x CPU throttle; `STRESS=full` runs the larger counts)
- `npm run qa:zen` runs `qa/zen.mjs`: Zen on and off in Bento, List and Icons, vertical centring, width, rapid toggling, and the path without View Transitions
- `npm run qa:icons` runs `qa/icon-solver.mjs` (the row solver on the real catalogue and on seeded random input: every tool once, rows within the column count, the minimum number of rows, order kept, the same output on 100 runs) and `qa/icons-switch.mjs` (no plate visible 16 ms after a switch, no sideways snap when the entrance ends, rows centred, the outgoing grid removed, ten rapid view toggles, reduced motion, a 390 px check, two balanced rows with no overlaps and 12 px plate gaps at 1280 and 1707 px in Zen and LTR/RTL, and the closed-plate rendering) followed by `qa/icons-schema.mjs` (the manifest schema accepts and rejects the Harvest contract fields, and `icons/manifest.v2.json` validates against it with `ajv`)
- `npm run qa:cards` runs `qa/card-layout.mjs` against `dist/`: every card in Bento and Icons view, English and Arabic, on the real catalog and on generated catalogs of 1 to 13 tools (1 to 16 with `--full`). It fails when the QR chip overlaps the icon, title, chips, badges, new dot, digit badge or label, when the New dot or the digit badge leaves the grid, when the icon overlaps the title or badges, when anything leaves its card, when the badges and the QR chip are not centred on one line, when a title is cut without an ellipsis, or when the page scrolls sideways. It also checks that the QR chip follows the hover parallax. The default run covers four viewports, two looks and two corner sets; `node qa/card-layout.mjs --full` covers nine viewports from 1920×1080 to 360×740, light and dark, all four looks and all three corner sets
- `npm run qa:tiles` runs `qa/tile-contrast.mjs`: it screenshots the middle of every glyph tile in Bento and Icons view for Core, Tools and Experimental in Vivid, Curated, Mono and Muted, light and dark, and fails when the glyph colour against it (white, or the ink colour in Muted) is below 3.0:1. It prints the five lowest ratios
- `npm run qa:motion` runs `qa/motion-lint.mjs`: it reads the computed transitions and animations of tiles, plates, palette rows, controls-pill buttons, the search bar, the tab rail and variant chips in every view, look and theme, and fails on any layout or paint property. There are no allowlisted selectors: the List row hover ring is a static inset `box-shadow` on `.app-card--row::after` that only fades its `opacity`.
- `npm run qa:search` runs `qa/search.mjs` (189 checks of `src/search.js` on the real catalogue: tiers, fields, Arabic folding, typos, AND, URL paste, layout swap, ranges, incremental results equal to cold results, and speed limits on the real and on a seeded 5000-entry catalogue). The palette side (via line, highlight, wrong-layout query, Arabic UI, command typo) is checked by `qa/search-ui.mjs`, which runs inside `qa:behaviour`
- `npm run qa:smooth` runs `qa/smooth.mjs`: a serpentine hover sweep over the tiles, ten palette open and close cycles and ten tab switches, sampled at 1× and 4× CPU throttle, reporting p50, p95 and long animation frames. It asserts the limits only with `--timing`, so run that on real hardware; it is not part of `check`
- `npm run qa:comments` runs `qa/no-comments.mjs`, which fails when the diff against `origin/main` (or the ref passed as its first argument) adds a code comment to `src/`, `build/`, `qa/`, `tools/`, `perf/`, `harvest/`, `compare.html` or `vercel.json`. `<!--LX:` markers and URLs are allowed (if the ref cannot be resolved it stops with a message to run `git fetch origin main`)
- `npm run check` is what CI runs: `qa:comments`, `qa:search`, build, `qa:quick`, `qa:cards`, `qa:tiles`, `qa:load`, `qa:behaviour`, `qa:qr`, `qa:zen`, `qa:icons`, `perf --assert` and `qa:motion`
- `perf/RESULTS.md` lists the baseline and final value of every measured metric, generated by `node perf/results.mjs`
- The `qa` GitHub Actions workflow (`.github/workflows/qa.yml`) runs `npm run check` on every push and pull request and uploads `qa/out/` and `perf/out/`. The site deploys through Vercel, so there is no deploy workflow
